Parallelised Julia sets

March 2026 · C++, GPU computing, WebGPU, OpenCL, parallel algorithms

Overview

TLDR: Check out the WebGPU demo at the bottom!

Julia sets are slightly lesser known but similarly produced fractal cousins of the Mandelbrot set. They arise from the asymptotic behaviour of repeated iterates of non-constant meromorphic functions mapping the Riemann sphere onto itself. Each such function defines a unique Julia set. Here, we look at the most widely studied family, defined by the quadratic polynomial \[ p(z) = z^2 + c , \] for some complex number \(c \in \mathbb{C}\).

A complex number belongs to the (filled) Julia set for the complex polynomial \(p\) if, under repeated iterations of the operation \(p\), its value does not spiral out to infinity. That is to say that \(z \in \mathbb{C} \) is in the set if the complex value \[ p^n(z) = \underbrace{p(p(\ldots p(}_{\times n} \!z) \ldots)) \] remains bounded as \(n\) tends to infinity.

Implementation

Whether a specific complex number is in a Julia set for a polynomial \(p\) depends only on the number itself and so a naive method for calculating a pictorial representation of a Julia set involves simply assigning a complex number to each pixel and then performing repeated iterations of \(p\) until a desired tolerance is reached.

It can be shown that, if \(|p^n(z)|\) exceeds the escape radius \(R = \max(2, |c|)\) for some \(n\), then the value will approach infinity with larger \(n\) and the point will not be in the set. For the value of \(c\) used in the benchmark below, this radius is \(2\). For each point, the code performs up to \(1000\) iterations of \(p\) and assigns a colour depending on how many iterations it took for the value to exceed the escape radius (if at all). To produce smoother colour gradients, the value produced estimates a continuous escape time based on how far the value of \(|p^n(z)|\) travels beyond the escape radius.

Results

The image above was produced using this C++ implementation. To compare the different approaches, I benchmarked the time taken to render a \(6400 \times 4000\) image, with up to 1000 iterations per pixel. The benchmark was run on my laptop, which has integrated Intel graphics.

Implementation Time Speed-up
Plain CPU 33.1631 s 1×
Multithreaded CPU 4.68771 s 7.1×
GPU (OpenCL) 0.193511 s 171×

The GPU implementation is approximately 171 times faster than the plain CPU version and around 24 times faster than the multithreaded implementation. Even with integrated graphics, the GPU version easily exploits the embarrassingly parallel naive approximation.

The benchmark uses the fixed complex constant \(c = -0.7 + 0.256i\), at a resolution of \(6400 \times 4000\) pixels, with the time being taken as the mean of three benchmark trials.
